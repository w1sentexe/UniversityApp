Расписание в Docker-образе
-------------------------

Исходники расписания находятся в `tools/schedule_import/files/`. При обновлении
замените старые Excel-файлы новыми и включите их в коммит. Локальная БД `data/`
и её резервные копии исключены из Git и контекста Docker.

При сборке Docker запускает `python -m tools.schedule_import --strict` и создаёт
готовую SQLite-базу `/opt/vsuet/schedule.sqlite3`. Она содержит расписание из Excel
и пустые таблицы рейтинга. Пропущенный файл, пустая выгрузка или повтор группы
между файлами останавливают сборку.

При старте контейнера entrypoint переносит только таблицу `group_schedule` в
рабочую БД, указанную в `DB_PATH` (на VPS — `/data/rating.sqlite3`). Существующие
студенты, оценки и рейтинги сохраняются. Перед изменением существующей БД
создаётся согласованная резервная копия в `/data/backups/`; замена выполняется
одной транзакцией. При совпадении расписания запись и резервное копирование
пропускаются. Ошибка установки останавливает запуск API.

База внутри образа хранится вне `/data`, поэтому существующий Docker-том не
скрывает новое расписание. Каждый запуск контейнера приводит расписание к версии
из образа; откат на предыдущий образ также возвращает его расписание.

Проверка и публикация
--------------------

Локальные проверки:

```bash
uv sync --locked
uv run python -m tools.schedule_import --strict --dry-run
docker build -t vsuet-schedule-check .
```

Pull request в `main` запускает линтер, пробную сборку образа и проверку установки
расписания при запуске контейнера. После слияния Action собирает образ, публикует его в GHCR и
разворачивает на VPS. Каждый push в `main` собирает образ, в том числе когда
изменились только Excel-файлы. Сборки и деплои выполняются последовательно.
Деплой использует код того же коммита, что и образ, ждёт успешной проверки API
и пересоздаёт nginx после замены backend-контейнера, чтобы применить новый
файл конфигурации и адрес backend. Версия образа — `1.0.(GITHUB_RUN_NUMBER - 1)`,
как в серверной ветке; создавать Git-теги при деплое не требуется.

На VPS должны быть настроены `.env` по `.env.example`, существующий том
`sqlite-data`, nginx и Docker Compose с поддержкой `up --wait`.
Используются GitHub Secrets `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`, `VPS_SSH_PORT`
и `VPS_PROJECT_PATH`; публикация и скачивание образа используют `GITHUB_TOKEN`.

Адрес образа вычисляется из владельца GitHub-репозитория и передаётся в Compose
через `BACKEND_IMAGE`. После успешного деплоя адрес и версия сохраняются на VPS
в `.deploy-image.env` (файл исключён из Git). Для ручного запуска той же версии:

```bash
docker compose --env-file .deploy-image.env -f docker-compose.prod.yml up -d --wait app
```

Не удаляйте том через `docker compose down -v`: он содержит рабочую БД и её копии.
